---------------------------------------------------------
Schéma XML pour la transmission de relevés en format XML.
---------------------------------------------------------

Revenu QUEBEC, 28 octobre 2025.

Ce document fournit des renseignements techniques sur l'utilisation du schéma XML pour la 
transmission des relevés en format XML.


1. TERMINOLOGIE

	Les termes schéma et schéma XML désignent le langage qui définit les structures et les 
	contraintes de contenu de documents XML décrites dans la spécification « W3C XML Schema 
	Part 1 », disponible à l'adresse http://www.w3.org/TR/xmlschema-1/. Ce langage est utilisé 
	pour construire et contrôler la validité des documents XML. 

	Le terme document XML désigne un document texte conforme à la spécification « W3C XML 1.0 », 
	disponible à l'adresse http://www.w3.org/TR/REC-xml/. Un document XML est valide quand sa structure
	est conforme au schéma XML qui lui est associé.


2. STRUCTURE DES FICHIERS

	Le schéma XML pour la transmission des relevés en format XML est constitué de plusieurs 
	fichiers portant l'extension .xsd. Ce découpage en plusieurs fichiers permet de retrouver plus 
	facilement l'information recherchée. 

	Pour valider un document XML, vous devez utiliser le fichier principal du schéma, nommé 
	Transmission.xsd, qui inclut par référence tous les autres fichiers.


3. ESPACE DE NOMS

	L'utilisation d'un espace de noms (« namespace ») permet d'uniformiser la nomenclature des 
	éléments et des attributs propres à un domaine d'application, et vise à prévenir les conflits 
	de noms dans les documents XML.

	L'espace de noms est spécifié dans l'attribut « targetNamespace » de l'élément racine du schéma. 
	L'espace de noms du schéma pour la transmission des relevés est le suivant : 
	http://www.mrq.gouv.qc.ca/T5. Ce nom a le format d'une adresse Internet qui conduit à de 
	l'information sur le schéma (cette adresse n'est pas disponible présentement). 
	

4. VERSION

	L'attribut Version indique la version d'un schéma. Par exemple :
	
		<xsd:schema targetNamespace="http://www.mrq.gouv.qc.ca/T5" version="2025.1" ...>

	Les schémas peuvent évoluer et Revenu QUEBEC peut décider de ne plus supporter des versions désuètes.  
	Vous devez donc surveiller les annonces de mises à jour des schémas et, s'il y a lieu, télécharger la 
	dernière version du schéma. Les modifications aux schémas sont indiquées dans le fichier
	/fr/Modifications.txt.

	IMPORTANT: Un document de transmission de relevés doit indiquer, dans l'attribut VersionSchema 
	de l'élément Transmission, la version de schéma que vous avez utilisée pour construire le 
	document. Cette information permet aux applications de valider le document avec la version du schéma
	que vous avez utilisée. Par exemple :

		<Transmission VersionSchema="2025.1" xmlns="http://www.mrq.gouv.qc.ca/T5">
    

5. SCHÉMA ET ESPACE DE NOMS
	
	Le fichier de transmission contient une référence à l'espace de noms à travers l'attribut 
	« xmlns ». Cet attribut fait le lien entre les définitions du 
	schéma et les balises utilisées dans la transmission.
	
	Certains analyseurs demandent l'utilisation d'un lien direct entre l'espace de noms et le schéma.  
	Ils requièrent un attribut défini dans l'espace de noms des schémas XML : « schemaLocation ». 
	Cet attribut prend deux paramètres, le premier est l'espace de noms pour les transmissions et le 
	second l'URI pour trouver le fichier du schéma. Comme il s'agit d'un attribut d'un autre schéma, 
	il faut définir l'espace de noms de ce schéma avec le même attribut que précédemment « xmlns ». 
	Par exemple :
	
	        <Transmission VersionSchema="2025.1" xmlns="http://www.mrq.gouv.qc.ca/T5"
	                      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
                              xsi:schemaLocation="http://www.mrq.gouv.qc.ca/T5 Transmission.xsd">

	Pour que l'exemple fonctionne, le fichier de transmission doit se trouver dans le même dossier 
	que le schéma.

7. ENCODAGE ET CARACTÈRES SPÉCIAUX

	Le fichier en format XML doit obligatoirement indiquer son encodage. Vous devez déclarer cet 
	encodage dans l'en-tête du fichier comme dans cet exemple : <?xml version="1.0" encoding="ISO-8859-1"?>. 
	Il existe plusieurs formes d'encodage qui correspondent en gros à l'environnement que 
	vous utilisez. On compte parmi les plus fréquents les encodages ISO-8859-1 et UTF-8. Il est primordial 
	que la balise de déclaration de l'encodage reflète bien celui utilisé dans votre fichier. (extrait du 
	IN-800 à la section 5.2.2).

	Remplacez les caractères spéciaux (<, >, ', " et &) par leur entité XML correspondante (&lt;, &gt;, &apos;, 
	&quot; et &amp;) dans le contenu des champs alphanumériques. Vous pouvez inclure tels quels les 
	caractères " et ' dans le contenu d'un champ. Notez qu'il n'existe que ces 5 entités en XML contrairement 
	au HTML qui en compte une multitude. Il n'est pas nécessaire de remplacer d'autres caractères par une 
	entité hexadécimale car le caractère peut être utilisé directement.
	
	Exemples corrects:
		<Ligne1>3800, rue Cité de l'Ampoule</Ligne1>
		<Ligne1>3800, rue Cité de l&apos;Ampoule</Ligne1>

		L'accent n'est pas remplacé car l'encodage permet de le représenter.
