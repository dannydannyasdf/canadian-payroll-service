-------------------------------------------------------------
XML schema for transmitting RL-slip data files in XML format.
-------------------------------------------------------------

Revenu QUEBEC, October 28, 2025

This document provides technical information on the use of schemas for transmitting 
RL-slip data files in XML format.


1. TERMINOLOGY

	The terms "schema" and "XML schema" refer to the language that defines the structure 
	and constrains the content of XML documents, as described in specification
	"W3C XML Schema Part 1," available at http://www.w3.org/TR/xmlschema-1/. 
	This language is used to construct and validate XML documents.

	The term "XML document" refers to a text document that conforms to specification 
	"W3C XML 1.0," available at http://www.w3.org/TR/REC-xml/. An XML document is valid when 
	its structure conforms to the corresponding schema.


2. FILE STRUCTURE

	The schema for transmitting RL-slip data files in XML format comprises several files 
	having the extension .xsd, as dividing the data into several files facilitates retrieval.

	To validate an XML document, you must use the schema's master file (Transmission.xsd), 
	which includes all the other files by reference.


3. NAMESPACE

	A namespace is used to standardize the nomenclature of the elements and attributes
	specific to an application domain and to prevent name conflicts in XML documents.

	The namespace is specified in the "targetNamespace" attribute of the schema root element. 
	The schema namespace for the transmission of RL-slip data is: 
	http://www.mrq.gouv.qc.ca/T5. This name has the format of an Internet address that leads to 
	information on the schema (this address is not yet available).


4. VERSION

	The "version" attribute indicates the version of a schema, e.g., 
		<xsd:schema targetNamespace="http://www.mrq.gouv.qc.ca/T5" version="2025.1" ...>

	Schemas are subject to change, and Revenu QUEBEC may decide to no longer support obsolete versions.
	You must therefore watch for announcements of schema updates and, if applicable, download the
	latest version. Changes to the schemas are given in the /en/Change-log.txt.

	IMPORTANT: The schema version used to construct an RL-slip data transmission document 
	must be indicated in the VersionSchema attribute of the Transmission element. 
	This information enables the applications to validate the document using the same version
	of the schema that you used, e.g.,
		<Transmission VersionSchema="2025.1" xmlns="http://www.mrq.gouv.qc.ca/T5">


5. SCHEMA AND NAMESPACE
	
	A transmission file contains a reference to a namespace through the "xmlns" attribute. This 
	links the definitions made in the schema and the tags used in the transmission file.

	Some validating parsers require an actual reference to the schema file in order to perform 
	the validation.	This is done with an attribute found in the schema namespace called 
	"schemaLocation". This attribute use two parameters, the first is the namespace for the schema 
	and the second is the URI to the schema definition file. Since it is an attribute from another
	schema, its namespace must be defined in order to be used, this is done with the same attribute 
	as before: "xmlns", e.g.,
	        <Transmission VersionSchema="2025.1" xmlns="http://www.mrq.gouv.qc.ca/T5"
	                      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
                              xsi:schemaLocation="http://www.mrq.gouv.qc.ca/T5 Transmission.xsd">

	In order for this definition to work, the transmission file must be in the same folder as the 
	schema files.

7. CODING AND SPECIAL CHARACTERS

	XML files must indicate their encoding, and you must state this encoding in the file header as 
	follows: <?xml version="1.0" encoding="ISO-8859-1"?>. A number of forms of encoding correspond 
	in general to the environment you use. The most frequent encodings are ISO-8859-1 and UTF-8. The 
	encoding tag must reflect the encoding used in your file. (extract from	IN-800.V section 5.2.2).

	Replace the special characters <, >, ', " and & with their corresponding XML entity (&lt;, &gt;,
	&apos;, &quot; and &amp;) in the content of alphanumeric fields. You may include the characters 
	" and ' as is in the content of a field. Note that there are only those 5 entities defined in
	XML while there are a number of others in HTML. It is not useful to use hexadecimal entity since
	your encoding includes the needed characters.

	Correct samples:
		<Ligne1>3800, rue Cité de l'Ampoule</Ligne1>
		<Ligne1>3800, rue Cité de l&apos;Ampoule</Ligne1>

		The accented character is not replaced by its hexadecimal value since the encoding allows for 
		its presence.
